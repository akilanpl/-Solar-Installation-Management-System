# API contracts

Implemented routes are the FastAPI application. The machine-readable contract is `contracts/generated/openapi.json`, generated by `apps/api/scripts/export_openapi.py`. The web client imports `apps/web/src/generated/schema.ts`, generated from that file. If the two disagree, regenerate both rather than editing the TypeScript by hand.

Planned routes below are not registered. Calling them returns 404 `not_found`.

## Conventions

- Prefix: `/api/v1`
- Ids: UUID
- Times: ISO 8601 from `timestamptz`
- Money: integer minor units, field suffix `_minor`, plus `currency_code`
- Capacity: integer watts
- Lists: `page` (default 1), `page_size` (max 100), `items`, `total`
- Errors: `{"error": {"code", "message", "details"}}`
- Unsafe requests: `X-CSRF-Token` matching cookie `solarops_csrf`, and a trusted `Origin` when the browser sends one
- Creates that must not duplicate: `Idempotency-Key` header, 8–80 characters from `[A-Za-z0-9_-]`

Login policy: an unverified customer receives 403 `email_not_verified`. A wrong password or unknown identifier receives 401 `invalid_credentials`. Employee login looks up `employee_profiles.employee_code`. Customer login looks up email and requires role `customer`.

Ownership: the customer id is taken from the session inside `create_enquiry`. The body cannot set `customer_user_id`, `status`, or `reference` (`extra="forbid"` on `EnquiryCreate`).

Each row is a contract for a later phase. Authentication is a session cookie unless noted. State changes are idempotent when they create a document (payment intent, order, ticket): the client sends `Idempotency-Key`. Updates that only move a state reject illegal transitions with 409.

## Idempotency and errors for planned writes

- Missing key on a create that requires one: 400 `idempotency_key_required`.
- Same key and same body: return the original resource.
- Same key and different body: 409 `idempotency_conflict`.
- Illegal status: 409 `invalid_transition`.
- Wrong owner: 404 `not_found` when revealing existence would leak another customer's data; 403 `forbidden` when the role cannot use the route at all.
- Provider not configured: 503 with a specific code. Do not answer 200.
